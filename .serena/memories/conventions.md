# Project conventions
- Keep gameplay/domain logic in `common`; loader modules should remain thin adapters/event bridges/storage implementations.
- Prefer Architectury events/APIs and `@ExpectPlatform` for loader-specific behavior; only use Mixins when no stable API hook exists. Required Mixins are a version-maintenance hotspot.
- Server-authoritative mutations must run on the Minecraft server thread. Existing core services frequently assert `server.isSameThread()`; preserve that invariant.
- Networking queues C2S work onto the server thread, rate-limits client requests, and performs permission/capability checks server-side. Never trust client-provided board/NPC/admin/action state without revalidation.
- Persistent state belongs in `RotasData`/SavedData or dedicated SavedData (e.g. stables); mark progress/data dirty after mutation and sync client snapshots through `RotasNetwork` rather than mutating client state directly.
- Data-driven kernel content is prepared/validated before apply; preserve revision/hash/history/draft validation and bounded input limits.
- Natural monster leveling and configured monster leveling are intentionally separate: natural config caps at 100; explicit monster setup uses `MonsterLevels.ABSOLUTE_MAX = 999`.
- Hot paths avoid world-wide scans: use tracked entities, bounded queues/timers, once-per-second work, and per-player loops. Preserve these bounds for new tick logic.
- Player-facing Thai strings should go through the localization/ThaiText layer; English/Thai lang parity is tested.
- Backward-compat constructors/serialization migrations are common. When changing records/config schemas, preserve old arities/fields or add explicit migration/sanitization.
- Existing legacy quest stack (`QuestService`) and kernel quest stack (`QuestKernelService`) are both live. Do not silently move behavior between them without tracing callers/UI/network paths.
